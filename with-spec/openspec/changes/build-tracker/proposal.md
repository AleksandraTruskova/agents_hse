# Proposal

## Why

Учебный прогресс на неделю сейчас нигде не фиксируется: нет единого места, где видны задачи, запланированные на них часы и доля выполненного. Нужен автономный мини-трекер учебных задач, который работает локально в браузере без CDN, внешних библиотек и API-ключей и сразу показывает прогресс по часам.

## What Changes

- Добавляется модульная структура приложения (вариант B): `index.html`, `styles.css`, `app.mjs`, `domain.mjs` и `tests/acceptance.test.mjs`.
- Задача имеет поля: `id`, `title`, `hours`, `done`. Стартовый пример: «Чтение» — 2 ч, done=true; «Практика» — 4 ч, done=false; «Повторение» — 2 ч, done=false.
- Добавление, удаление и переключение `done` реально меняют данные и обновляют интерфейс.
- Валидация формы: название непустое после trim; часы — число от 0,5 до 24 с шагом 0,5; пустое значение часов не равно нулю. Ошибка показывается рядом с полем, введённые значения формы сохраняются для исправления.
- Итоговые часы и прогресс = округление(100 × сумма часов done / сумма часов всех задач); при отсутствии задач — 0% без NaN/Infinity.
- Фильтр «активные/все» влияет только на видимый список; итоговые часы и прогресс считаются по всем задачам.
- Задачи сохраняются в localStorage; при недоступном хранилище показывается понятное сообщение, работа продолжается в памяти.
- Интерфейс читаем на ширине 390 px без горизонтального скролла; поля и кнопки подписаны.
- Добавляется приёмочный тест `tests/acceptance.test.mjs`, покрывающий сценарии T1–T5 из checks.md.

Вне scope: однофайловый вариант A (`tracker-v2.html`) и любые серверные компоненты — не создаются.

## Capabilities

### New Capabilities

- `tracker`: управление списком учебных задач на неделю — добавление, удаление, переключение готовности, валидация ввода, фильтрация видимого списка, расчёт итоговых часов и прогресса по часам, сохранение в localStorage с деградацией в память.

## Impact

- Новые файлы в корне проекта: `index.html`, `styles.css`, `app.mjs`, `domain.mjs`, `tests/acceptance.test.mjs`.
- Зависимости: нет внешних библиотек и CDN; приложение работает в браузере напрямую с файловой системы или простого статического сервера.
- Тесты: `tests/acceptance.test.mjs` запускается через Node.js (встроенный test-runner), без дополнительных пакетов.
- Существующие файлы проекта (`brief.md`, `checks.md`, `openspec/`) не изменяются.
