# Design

## Context

Greenfield-проект: вне `openspec/` нет кода, тестов и сборки. Мотивация и требования — в `proposal.md` и `specs/tracker/spec.md` (сценарии T1–T5 из `checks.md`). Жёсткие ограничения: без CDN, внешних библиотек и API-ключей; целевой запуск — в браузере; приёмочные проверки — из `checks.md`.

## Goals / Non-Goals

**Goals:**

- Разделить чистую доменную логику (модель задачи, валидация, прогресс, фильтр, хранилище) и работу с DOM так, чтобы поведение можно было проверять в Node.js без браузера.
- Сделать автономность проверяемой: тесты и приложение используют только стандартные возможности браузера и Node.js.
- Обеспечить деградацию при недоступном localStorage без потери работоспособности.

**Non-Goals:**

- Серверная часть, синхронизация между устройствами, авторизация.
- Онофайловый вариант A (`tracker-v2.html`) — исключён по решению пользователя.
- Редактирование существующей задачи (бриф требует только добавление, удаление, переключение `done`).
- Визуальное тестирование в реальном браузере автоматизированными средствами (jsdom/playwright запрещены ограничением автономности); проверка вёрстки на 390 px — ручная, по `checks.md`.

## Decisions

### 1. Два слоя: `domain.mjs` (без DOM) и `app.mjs` (DOM + события)

`domain.mjs` содержит: тип задачи (`{id, title, hours, done}`), функции валидации, расчёта итогов и прогресса, применения фильтра, операции добавления/удаления/переключения и репозиторий хранилища. `app.mjs` импортирует `domain.mjs`, рендерит список и итоги, обрабатывает события формы и перерисовывает интерфейс после каждой операции.

- Почему: приёмочный тест `tests/acceptance.test.mjs` исполняется через встроенный test-runner Node (`node --test`) и импортирует `domain.mjs` напрямую — сценарии T1–T5 проверяются без браузера.
- Альтернатива: вся логика в `app.mjs` рядом с DOM — отвергнута: без DOM-слоя сценарии нельзя проверить в Node без внешних зависимостей.

### 2. Репозиторий хранилища с fallback в память

В `domain.mjs` — тонкая обёртка storage: при старте пробуется `localStorage` (запись/чтение тестового ключа в `try/catch`); при недоступности используется in-memory реализация того же интерфейса, а `app.mjs` показывает баннер «Сохранение недоступно, данные живут до закрытия вкладки». Каждая мутация сразу сохраняется.

- Почему: требование спеки о деградации, а тестам нужен детерминированный in-memory storage без браузера.
- Альтернатива: прямые обращения к `localStorage` из `app.mjs` — отвергнута: не тестируемо и смешивает слои.

### 3. Расчёт прогресса с явной защитой от деления на ноль

`progress = totalHours > 0 ? Math.round(100 * doneHours / totalHours) : 0` — единственная формула, NaN/Infinity исключены конструкцией, а не последующими проверками. Итоговые часы и прогресс всегда считаются по полному списку; фильтр применяется только к копии для отображения.

### 4. Валидация часов как числовая, а не строковая

Парсинг через `Number(raw)` с проверками: не пустая строка до парсинга, `Number.isFinite`, `0,5 ≤ h ≤ 24`, `h * 2` — целое (шаг 0,5). Пустое значение даёт ошибку «укажите часы» и не приравнивается к нулю. Ошибки выводятся в элемент рядом с соответствующим полем; значения формы не сбрасываются при неудачной отправке.

- Альтернатива: регулярные выражения по строке — отвергнута: числовые проверки проще и точнее для границ и шага.

### 5. Запуск приложения — через локальный статический сервер

ES-модули (`<script type="module" src="./app.mjs">`) браузеры блокируют при открытии файла напрямую (`file://`, CORS). Приложение рассчитано на запуск через любой статический сервер из корня проекта, например `python -m http.server` или `npx http-server`, с открытием `http://localhost:8000/`. Тесты (`node --test`) от способа запуска UI не зависят.

- Альтернатива: отказ от модулей в пользу одного глобального скрипта — отвергнута: вариант B задан брифом как модульная структура (`app.mjs`, `domain.mjs`).

### 6. Идентификаторы задач

`crypto.randomUUID()` при доступности, иначе fallback на `Date.now()` + монотонный счётчик. Стабильный уникальный `id` нужен для ключей списка и переключения/удаления по задаче.

## Risks / Trade-offs

- ES-модули не работают с `file://` → сервер из Decision 5; инструкция по запуску должна быть в интерфейсе репозитория (README или комментарий в `index.html`).
- `localStorage` может быть запрещён (приватный режим, политики) → fallback в память + баннер (Decision 2); данные при закрытии вкладки теряются — это осознанный trade-off деградации.
- `Math.round` прогресса: ровные значения (25%, 75%) совпадают с `checks.md`; неравномерные наборы часов могут давать округление «визуально спорным» — принято, требования спеки соблюдены.
- Без автоматизированных браузерных тестов: сценарии T1–T5 покрываются на уровне домена, но рендер, подписи и ширина 390 px проверяются вручную — фиксируется в задачах, не заявляется как автоматическая проверка.

## Migration Plan

Не требуется: система новая, существующих пользователей и данных нет. Развёртывание — копирование файлов `index.html`, `styles.css`, `app.mjs`, `domain.mjs` на любой статический хостинг или локальный сервер. Откат — удаление этих файлов.
